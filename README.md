# REA Typora Project · 0.14.0

一个以 Typora 编辑体验为目标、分阶段实现的独立 macOS Markdown 编辑器。应用名称为 **REA Markdown**，使用 **Swift / AppKit + WKWebView + Milkdown Crepe**。目前可以在本机打开、编辑、保存 Markdown，并处理本地图片与图片剪贴板。

**当前是可运行的阶段版本，不是完整 Typora 替代品。** 项目与 Typora 官方无隶属关系。图标采用项目所有者指定的 Typora 原版图标，资源归属和许可证边界见 [第三方声明](THIRD_PARTY_NOTICES.md)。

**当前源码和下载版本：0.14.0；另提供 0.13.0 下载。** 0.13.0 新增工作空间文档/文件夹创建，0.14.0 新增最近文档；两版核心实机流程已验收，通过后同步源码及下载包。

[下载 0.14.0](https://github.com/TheShyWR/REA-Typora-Project/releases/tag/v0.14.0) · [版本记录](CHANGELOG.md) · [完成度评估](docs/PROGRESS.md) · [验收说明](docs/VALIDATION.md)

## 目前能做什么

- 打开和保存 UTF-8 `.md`、`.markdown`、`.txt`，支持新建、另存为。
- 排版编辑与源码模式切换；基础标题、行内格式、列表、引用、任务列表、表格和代码编辑由 Milkdown 提供。基础列表键盘操作已有原版样例对照，其他复杂行为仍需补测。
- 无编辑保存保留原始字节，包括 UTF-8 BOM 和 CRLF；无法可靠往返的语法自动进入源码保护，可继续编辑保存，不将它误当作已完整支持的富文本语法。
- 主动提示当前磁盘文件外部修改或删除，支持确认后重新载入或另存为，避免直接覆盖；本地恢复草稿支持异常退出后的未保存内容恢复。
- 显示本地图片，保留中文相对路径和替代文本；插入按钮自动复制图片到文档旁的附件目录，跨目录另存为可复制引用到的本地相对图片。
- 排版模式支持图片粘贴。已实测从 macOS 预览复制图片内容、从 Finder 复制 PNG 文件；撤销、重做、保存并重启重开后仍可显示。
- 可逐层展开的目录树、磁盘变化自动更新、手动刷新、当前文档高亮与定位及同目录重命名；目录优先排序，支持中文和空格路径。
- 当前文档查找与替换：匹配数量、上一个/下一个、大小写选项、单次和全部替换；支持排版与源码模式及撤销。
- 跨文件搜索工作空间内已保存的 UTF-8 Markdown/文本，含嵌套目录、大小写选项、路径与行号预览，点击结果定位到源码。
- 标准 YAML Front Matter 可与正文同时排版编辑，支持原样保存、插入、搜索与撤销；仍以安全往返检查为前提。
- 基础大纲、段落专注与排版打字机模式；主题、字体、字号、行距和排版宽度可调整并跨重启保留。
- 提供初步 PDF 导出入口，完整排版和资源质量尚未验收。

## 完成度：0.14.0 暂维持约 46%

按既定的 macOS Typora 1.9.4 功能范围与 8 项权重，0.13.0 与 0.14.0 均暂维持 **约 46%**（41%–51%），与 0.12.0 相同；两版核心界面操作已通过实机验收；本次保守保持既有评分，不重复加分。0.5.0 的约 35% 保留为历史基线。这是基于实现和验收证据的人工工程评估，不是自动测得的兼容率。

本版新增分数来自 YAML 元数据文本与正文共同编辑。符号显隐、复杂选区与输入法、扩展语法、附件迁移、完整主题、导出/打印、多窗口与性能仍有明显缺口。后续每版交付都会说明当前百分比及变化，详见 [评分表、证据与交付约定](docs/PROGRESS.md)。

- 构建目标：macOS 13.0+；尚未在全部旧系统版本验收。

## 从源码构建

需要 macOS、Xcode 或含 macOS SDK 的 Command Line Tools，以及 Node.js 22.12+（本机验证使用 Node.js 24）。

```sh
git clone https://github.com/TheShyWR/REA-Typora-Project.git
cd REA-Typora-Project
npm ci
npm run build:mac
open "release/REA Markdown.app"
```

远程 `main` 与 `v0.14.0` 提供最新源码；`v0.13.0` 保留上一阶段源码。两版 Release 均提供 ZIP 与 SHA-256。

`npm start` 会构建并打开；`npm run package:mac` 生成 ZIP 和 SHA-256 文件。构建采用当前 Mac 的 CPU 架构，Intel 构建尚未验收。构建中现有的 WebKit 文件类型 API 弃用、IIFE 动态语言加载警告尚未全部消除。

## 工作空间目录树（0.6.0）

点击侧栏“＋”或“文件 → 打开文件夹…”，展开各级目录后点击文档打开。刷新按钮重新读取目录并保留展开状态；定位按钮展开当前文档的父目录并聚焦该文件。两项操作也可从“文件”菜单调用。

仅展示普通目录和 `.md`、`.markdown`、`.txt` 文件，隐藏文件、符号链接和应用包不显示。按需读取展开的目录。0.8.0 增加自动更新与当前文件重命名，使用方式如下；0.9.0 增加跨文件搜索，0.13.0 增加新建文档和目录，文件移动尚未实现。工作空间和展开状态暂不跨应用重启保存。

## 查找与替换（0.7.0）

`⌘F` 打开搜索，`⌘G` / `⇧⌘G` 查找下一处 / 上一处；搜索框内 Enter / Shift+Enter 也可导航。按 Esc 关闭面板。可选区分大小写，替换内容留空表示删除。单次替换后继续定位下一处；全部替换使用一次可撤销编辑，按 `⌘Z` 撤销、`⇧⌘Z` 重做。

- 排版模式搜索排版文本（含 YAML 元数据），可跨相邻的粗体/普通文字，但不跨段落、图片等边界。图片替代文本与链接 URL 不计入正文匹配；未匹配区域格式和链接目标保留。
- 源码模式搜索原始 Markdown，包括标记、Front Matter 和链接地址。CRLF 文档在替换、撤销和保存后保留换行约定；磁盘 BOM 由文档存储层保留。
- 该面板仅支持文档内单行普通文本搜索，不支持正则、全词或跨文件替换；跨文件搜索使用下述独立面板。排版模式显示全部匹配高亮；源码模式使用当前匹配选区。超大文档和大量匹配的性能尚未专项验收。

## 文件监听与重命名（0.8.0）

所选工作空间根目录及已访问的子目录会监听磁盘条目变化，自动更新列表并保留展开状态；未变化的目录不会重建界面。当前文档单独监听，兼容原地写入、原子替换、删除及恢复；切回应用时也会重新检查。这里不是对整个工作空间进行递归扫描。

磁盘文件被外部修改、删除或无法读取时，顶部显示提示，编辑区保持原内容。点击“重新载入磁盘版本”才能加载磁盘内容；存在未保存修改时需要确认，取消后继续保留本地编辑。也可“另存为…”保留当前版本。常规保存仍会检查磁盘基线并拒绝冲突覆盖，没有自动合并。

保存当前文档后，点击侧栏或“文件”菜单的“重命名当前文件…”。只在同一目录修改文件名，支持 `.md`、`.markdown`、`.txt` 扩展名，不覆盖已有文件。窗口标题、目录高亮、后续保存和恢复草稿路径同步更新；编辑区和撤销历史不重建。原有附件目录和 Markdown 图片链接不改动，因父目录相同仍可读取。改名后新插入的图片可能进入新文件名对应的附件目录。

尚不支持重命名文件夹、跨目录移动或自动跟随外部改名。外部移走文件会显示删除/移动提示；在大小写不敏感的磁盘上仅更改大小写时，需要先使用中间名称。大量目录和网络卷尚未专项验收。

## 工作空间搜索（0.9.0）

打开文件夹后，点击侧栏“搜索工作空间…”或按 `⇧⌘F`，输入关键词并按 Enter / 点击“搜索”。搜索会递归读取尚未展开的子目录，返回相对路径、行号和文本片段，每个匹配行显示一条结果；支持区分大小写，匹配普通文本而非正则表达式。按 Esc 可关闭面板。

结果来自磁盘上**已保存的 Markdown 源码**，包括 Markdown 标记和链接地址，不包含编辑器中的未保存文字。点击结果会打开文档、切到源码模式并选中该行第一处匹配。切换前仍有未保存内容提醒；打开时校验内容指纹，文件变动后只打开当前内容并提示重新搜索，避免使用旧位置。

- 文件范围为 UTF-8 `.md`、`.markdown`、`.txt`；隐藏项、符号链接和应用包不遍历。大于 2 MiB、不可读、非 UTF-8 或含 NUL 的文件跳过并显示数量。
- 一次最多读取 1000 个文档、遍历 10000 个条目、返回 200 个匹配行，使用约 10 秒扫描预算；达到上限时明确提示结果不完整。扫描在后台执行，耗时文件系统读取不保证被立即打断。
- 结果是一次搜索的快照，修改关键词或切换工作空间会清空旧结果；文件变化后点击“搜索”更新。没有后台索引、跨文件批量替换、正则或全词搜索。
- 长行自动折行情况下的精确滚动、大型目录与网络卷性能仍待专项验收；不能把扫描上限视作完整大目录支持。

## 写作设置与打字机（0.10.0）

点击顶部“设置”或按 `⌘,`，可以选择浅色、深色或跟随系统，选择系统/衬线/等宽正文字体、14–22 的预设字号、三档行距和三档排版区域宽度。设置立即生效，自动保存到本机原生偏好；“恢复默认”可一次重置。正文宽度包含编辑器左右留白，窄窗口会按可用空间收缩。源码沿用等宽字体，并使用设置的字号与行距。

点击“打字机”或“视图 → 打字机模式”，在排版编辑中将输入光标保持在可视区域中部。拖选或保留非空选区时不强制居中，输入法组合事件期间暂停滚动；这些保护已有逻辑检查，真实候选窗口仍需专项实测。切到源码暂停打字机，回排版后恢复已保存的开关；目前不支持源码打字机。

设置不写入 Markdown，也不添加正文撤销步骤。设置面板打开时，编辑操作暂停；Esc 或“完成”返回编辑器。跟随系统根据 WebKit 的系统主题信号更新，运行中改变系统主题的实机验证仍待补充。尚无自定义主题导入、任意 CSS 编辑、全部字体枚举或完整偏好体系；公式/表格/图片的复杂滚动布局和导出表现仍待验收。

## YAML Front Matter（0.12.0）

支持文首以 `---` 包围的 YAML 文本块。满足安全往返检查的 LF 文档可直接在排版模式同时编辑元数据与正文，保留注释、引号、列表写法和缩进。顶部“元数据”或“文件 → 插入 YAML 元数据”可在文首插入默认块；已有元数据时只定位，不重复插入。在块内按 `⌘Enter` 进入正文编辑。

元数据与正文共用撤销/重做历史；文档搜索包含元数据文本，大纲只列正文标题。编辑器拒绝把元数据放到文中、嵌套或创建多块，也拒绝在块内插入独立的 `---` / `...` 分隔行；需要这些源文本结构时可在源码模式处理。

此阶段按文本保存元数据，不验证 YAML 值的语义，不执行 `typora-root-url`、图片复制目录、导出变量或其他配置。TOML、未闭合 YAML、CRLF/不支持的原始换行、结束标记和无法原样往返的格式继续进入源码保护。磁盘 UTF-8 BOM 仍由原生存储层保留；源码模式可继续编辑保存。含元数据的图片跨目录复制和 PDF 导出尚未开放，避免将未验收的配置行为当成支持。

## 工作空间创建（0.13.0）

打开工作空间后，点击侧栏“新建文档…”或“新建文件夹…”，选择工作空间内的父目录，再输入名称。文档不填扩展名时自动加 `.md`，也接受 `.markdown` 和 `.txt`。成功创建的文档会打开并在目录树定位；新建文件夹只刷新目录，不切换当前文档。

创建文档前沿用未保存提醒；取消不创建文件。同名项目、隐藏前缀、非法名称、工作空间外路径和符号链接均拒绝。若文件已创建但打开失败，会明确报告，并保留新文件供手动处理。尚未加入目录移动或重命名。本版原生存储及 JS 调用已有自动化验证，新建文档/文件夹、同名拒绝及取消未保存提醒已实机验证。

## 最近文档（0.14.0）

“文件 → 最近打开”保留最多 10 条成功打开或保存的文档，最近操作置顶且不重复。另存为保留原文件记录，应用内重命名替换旧路径。选择记录沿用未保存提醒；失效路径报错并保留当前文档。“清空最近记录”不删除磁盘文档。

记录保存在 `~/Library/Application Support/local.rea.markdown/recent-documents.json`，只包含路径。记录写入失败会提示，不撤销已完成的文档操作；损坏记录回退为空。磁盘持久化和独立进程读取已验证，应用退出重启、最近打开、取消未保存提醒及清空菜单已实机验证。尚无工作空间会话自动恢复。

## 图片与文档安全

先保存文档，再插入或粘贴图片。附件保存在 `<文档名>.assets/`，Markdown 使用相对链接。允许 PNG、JPEG、GIF、WebP；实机测试集中在 PNG。单张或一次粘贴/拖放批次总量最多 20 MB。

文件拖入排版区域已接入持久化导入流程，实际跨窗口拖放手势仍待验收。源码模式请使用顶部“图片”按钮。手动移动文档时需同时携带附件并保持目录结构。0.11.0 的跨目录另存为可复制相对图片，具体范围如下；撤销插图不会自动删除附件。

草稿存放在 `~/Library/Application Support/local.rea.markdown/Recovery/`，是本机明文恢复文件；显式保存才更新原文档。恢复不能保证捕获异常终止瞬间尚未从 WebKit 发出的字符；保存冲突检测也不是跨进程事务锁。

## 另存为与图片复制（0.11.0）

对已命名的文档选择“文件 → 另存为…”，保存对话框默认勾选“同时复制本地相对图片”。当目标目录改变时，应用识别 Markdown 行内图片及引用式图片，将实际引用到的 PNG/JPEG/GIF/WebP 复制到目标目录中的相同相对位置。Markdown 文本、alt、标题、链接写法、BOM 和换行约定保持不变；原文档与原图片不删除。同目录另存为不重复复制。

- 复制范围限于原文档目录内的相对图片，包含嵌套子目录和中文/空格路径；代码示例与普通超链接不作为图片处理。相同目标路径只处理一次。
- 同名且字节一致的图片复用；内容不同、文件缺失、路径包含符号链接或相对路径越出原目录时停止保存并提示。不会覆盖不同内容的已有图片。
- 单张沿用 20 MiB 限制，一次另存为图片总量最多 100 MiB。遇到可捕获的写入错误，会清理本次新建的图片和空目录；文档成功写入后若清理旧恢复草稿失败，会保留文档及图片并提示。
- HTML 图片、含图片的 Front Matter 文档暂不自动复制。远程、data URL 和绝对图片路径保持原样，不下载或复制，因此不能据此保证这些链接随文档迁移到别的电脑。
- 可取消勾选，仅另存文档，状态栏会提示图片未复制。取消保存对话框则不写入。已有附件不会自动清理；图片缩放、一般文件移动、目录外引用重写和完整附件管理仍未完成。

复制和文档保存不是跨文件的原子事务，强制退出、断电或外部并发修改仍可能留下附件；网络卷和大量附件尚未专项验收。新插入图片继续使用当前文档名的 `.assets` 目录，旧相对图片保持原有目录结构。

## 工程结构

```text
src/                      Web 编辑器、图片、源码保护和样式
native/                   AppKit / WebKit 桥及文档、图片存储
  Resources/AppIcon.icns   应用图标（第三方资源）
scripts/                  构建、打包、第三方许可收集
docs/                     完成度、验收和第三方许可
index.html                编辑器页面入口
vite.config.js            Web 资源构建配置
package.json              开发依赖与命令
package-lock.json         可复现依赖锁定
CHANGELOG.md              0.1.0—0.14.0 阶段记录
LICENSE                   仓库原有 MIT 许可证
THIRD_PARTY_NOTICES.md     第三方归属与许可证边界
```

`node_modules/`、`build/`、`dist/`、`release/` 是本机构建产物，不提交 Git。旧 Electron 实验、REA 分析转储、测试脚本和临时样例已按项目所有者要求移出发布工程；验收结论保留在文档中，本仓库当前不提供 `npm test` 命令。历史测试不等于每个未来提交都会自动验证。
