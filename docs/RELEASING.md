# 发布流程

项目所有者于 2026-10-26 明确要求：之后“提交到 GitHub”同时包含源码、README 与可下载版本。只推送源码或只创建标签不算完成发布。

1. 核对 package.json、锁文件与 Info.plist 的版本；保留工作区已有改动，确认该版本的功能验收与完成度记录。
2. 使用已验收的 `npm run package:mac` 产物，核对严格签名、ZIP、版本和 SHA-256；未修改代码时不重复构建已验收的包。应用当前为 macOS 13.0+ / Apple Silicon，ad-hoc 签名，尚未 Apple 公证。
3. 更新 README 的当前版本和下载链接、CHANGELOG、完成度与验收文档。测试样例、分析转储、构建目录、密钥与凭据不进入源码提交。
4. 提交源码，通过 SSH 推送 main 与对应版本标签；不可静默覆盖既有标签或已有 Release 附件。
5. 创建对应 GitHub Release，说明增量、完成度和限制，上传 `REA-Markdown-<版本>-macos-arm64.zip` 与同名 `.sha256`。SSH 处理 Git 推送；Release 元数据和附件通过已登录网页或已授权的 GitHub API 发布，不在仓库保存凭据。
6. 验证 Release 指向正确标签/提交、两个附件可下载，远程下载的 ZIP 与本机验收包字节一致，SHA-256 正确，再报告源码与下载链接。

更新 0.11.0 不补造 0.9.0、0.10.0 的独立历史发布，它们的功能和阶段记录包含在本版中。发布失败时明确区分本地提交、远程源码、标签、Release 和附件各自状态。
